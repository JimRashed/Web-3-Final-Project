# QuizArena API & Service Contracts

> **Historical (Milestone 2).** This describes the single aggregate host (`QuizArena.Api` + shared `QuizArenaContext`). The current architecture is six independent services. See the [Milestone 3 report](milestone3/architecture-and-reflection.md) and [API contracts](milestone3/api-contracts.md).

This document describes the HTTP API exposed by `QuizArena.Api` and the request/response contracts defined in `QuizArena.Domain`.

The routes and status codes below reflect the current controller implementations. Examples use representative values.

## API conventions

- Base URL: `https://localhost:7125` (or the host/port selected by the active launch profile).
- Content type for JSON requests and responses: `application/json`.
- Required request header for JSON bodies:

  ```http
  Content-Type: application/json
  ```

- The current API pipeline does not configure ASP.NET Core authentication middleware. An `Authorization` header is therefore not currently required by these endpoints.
- Controller model-binding failures produced by `[ApiController]` return `400 Bad Request`, normally using ASP.NET Core's `ValidationProblemDetails` shape.
- JSON property names below use the .NET record property names as emitted by the current default JSON configuration.
- Unless explicitly stated, an unhandled exception is returned by the hosting environment as `500 Internal Server Error`.

# Identity domain

## POST `/api/auth/register`

### Purpose
Creates a user account. The service hashes the supplied password before persisting the user. Usernames must be unique.

### Request

Headers:

```http
Content-Type: application/json
```

Body schema:

```json
{
  "username": "alex@example.com",
  "password": "CorrectHorseBatteryStaple!"
}
```

`RegisterRequest` properties:

| Property | Type | Required | Description |
|---|---|---:|---|
| `username` | string | Yes | New user's username. |
| `password` | string | Yes | Plain-text password supplied for hashing. |

### Responses

#### 200 OK

Returned when registration succeeds.

```json
{
  "userId": "8f7d2a15-2e7a-4a7d-8c3a-0f4e4d3f9a21",
  "username": "alex@example.com"
}
```

Response schema: `UserDto`.

#### 400 Bad Request

Returned when ASP.NET Core request binding or validation fails.

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.1",
  "title": "One or more validation errors occurred.",
  "status": 400,
  "errors": {
	"Username": ["The Username field is required."]
  }
}
```

#### 409 Conflict

Returned when the username already exists.

```text
Username already taken
```

## POST `/api/auth/login`

### Purpose
Authenticates a user and returns a signed JWT-like token generated by `AuthService`.

### Request

Headers:

```http
Content-Type: application/json
```

Body schema:

```json
{
  "username": "alex@example.com",
  "password": "CorrectHorseBatteryStaple!"
}
```

`LoginRequest` has the same two string properties as `RegisterRequest`.

### Responses

#### 200 OK

```json
{
  "userId": "8f7d2a15-2e7a-4a7d-8c3a-0f4e4d3f9a21",
  "username": "alex@example.com",
	"token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

Response schema: `LoginResponse`.

#### 400 Bad Request

Returned for invalid or incomplete JSON request data.

```json
{
  "title": "One or more validation errors occurred.",
  "status": 400,
  "errors": {
	"Password": ["The Password field is required."]
  }
}
```

#### 401 Unauthorized

Returned when the username is not found or the password is incorrect.

```text
Invalid username or password
```

## GET `/api/users/{id}`

### Purpose
Returns a user profile by GUID. The password hash is not included in the response.

### Request

Path parameter:

| Parameter | Type | Required | Example |
|---|---|---:|---|
| `id` | GUID | Yes | `8f7d2a15-2e7a-4a7d-8c3a-0f4e4d3f9a21` |

Example request:

```http
GET /api/users/8f7d2a15-2e7a-4a7d-8c3a-0f4e4d3f9a21
```

No request body is accepted.

### Responses

#### 200 OK

```json
{
  "userId": "8f7d2a15-2e7a-4a7d-8c3a-0f4e4d3f9a21",
  "username": "alex@example.com"
}
```

#### 400 Bad Request

Returned when `id` is not a valid GUID.

```json
{
  "title": "One or more validation errors occurred.",
  "status": 400,
  "errors": {
	"id": ["The value 'not-a-guid' is not valid for id."]
  }
}
```

#### 404 Not Found

Returned when no user exists for the supplied GUID. The current controller returns an empty response body.

# QuestionBank domain

## GET `/api/questions/generate`

### Purpose
Returns a random set of questions, including each question's category name.

### Request

Query parameter:

| Parameter | Type | Required | Default | Description |
|---|---|---:|---:|---|
| `count` | integer | No | `10` | Number of questions requested; must be greater than zero. |

Example request:

```http
GET /api/questions/generate?count=3
```

No request body is accepted.

### Responses

#### 200 OK

```json
[
  {
	"id": "d2719e4b-0b4b-4b68-a2e2-3aa4f37a12c1",
	"prompt": "Which planet is known as the Red Planet?",
	"category": "Science"
  },
  {
	"id": "c36a6f2a-8f08-4d88-bc88-6b7ca7bf7541",
	"prompt": "Who wrote Romeo and Juliet?",
	"category": "Literature"
  }
]
```

Response schema: array of `QuestionDto`.

#### 400 Bad Request

Returned when `count` is zero or negative.

```text
Count must be greater than zero.
```

A malformed query value also produces a model-binding validation response:

```json
{
  "title": "One or more validation errors occurred.",
  "status": 400,
  "errors": {
	"count": ["The value 'many' is not valid for count."]
  }
}
```

# Lobby domain

## POST `/api/lobbies/{joinCode}/lock`

### Purpose
Finds an active lobby by join code, changes its status to `Locked`, persists the change, and returns the players assigned to the lobby.

### Request

Path parameter:

| Parameter | Type | Required | Example |
|---|---|---:|---|
| `joinCode` | string | Yes | `QZ7K4P` |

Example request:

```http
POST /api/lobbies/QZ7K4P/lock
```

No request body is accepted.

### Responses

#### 200 OK

```json
{
  "lobbyId": "e2a3f8c1-90d1-4f9e-9ca4-4a91d7e7b8f2",
  "joinCode": "QZ7K4P",
  "status": "Locked",
  "playerIds": [
	"player-a",
	"player-b"
  ]
}
```

Response schema: `LobbyProvisionResponse`.

#### 404 Not Found

Returned when no lobby matches `joinCode`. The current controller returns an empty response body.

#### 500 Internal Server Error

Possible if persistence fails while saving the locked lobby.

# Gameplay domain

## POST `/matches`

### Purpose
Creates an active match and emits `MATCH_CREATED` notification events for both players.

### Request

Headers:

```http
Content-Type: application/json
```

Body schema:

```json
{
  "matchId": "match-2026-0001",
  "playerAId": "player-a",
  "playerBId": "player-b"
}
```

`CreateMatchRequest` properties:

| Property | Type | Required | Description |
|---|---|---:|---|
| `matchId` | string | Yes | Client-supplied match identifier. |
| `playerAId` | string | Yes | First player identifier. |
| `playerBId` | string | Yes | Second player identifier. |

### Responses

#### 201 Created

The `Location` header points to the created match resource.

```http
Location: /matches/match-2026-0001
```

```json
{
  "matchId": "match-2026-0001",
  "playerAId": "player-a",
  "playerBId": "player-b",
  "status": "ACTIVE",
  "playerAScore": 0,
  "playerBScore": 0,
  "currentQuestionIndex": 0
}
```

Response schema: `MatchResponse`.

#### 400 Bad Request

Returned for invalid or incomplete JSON request data.

```json
{
  "title": "One or more validation errors occurred.",
  "status": 400,
  "errors": {
	"PlayerAId": ["The PlayerAId field is required."]
  }
}
```

#### 500 Internal Server Error

Possible if match persistence or notification event persistence fails.

## GET `/matches/{matchId}/next-question`

### Purpose
Returns the next question for the match.

The current implementation obtains the question from an internal static mock-question list in `GameplayService`; it does not call the QuestionBank service for this operation.

### Request

Path parameter:

| Parameter | Type | Required | Example |
|---|---|---:|---|
| `matchId` | string | Yes | `match-2026-0001` |

Example request:

```http
GET /matches/match-2026-0001/next-question
```

### Responses

#### 200 OK

```json
{
  "questionId": "q-2",
  "text": "What is 2 + 2?",
  "options": ["3", "4", "5", "6"]
}
```

Response schema: `QuestionResponse`.

#### 500 Internal Server Error

If `matchId` does not exist, the service throws `Exception("Match not found")`. No controller-level `404` mapping currently exists, so the default hosting exception behavior applies.

## POST `/matches/{matchId}/answers`

### Purpose
Checks an answer, increments the submitting player's score when correct, advances the question index, and marks the match `FINISHED` after five questions. A completion notification is emitted for both players.

### Request

Headers:

```http
Content-Type: application/json
```

Path parameter:

| Parameter | Type | Required | Example |
|---|---|---:|---|
| `matchId` | string | Yes | `match-2026-0001` |

Body schema:

```json
{
  "userId": "player-a",
  "questionId": "q-2",
  "answer": "4"
}
```

`SubmitAnswerRequest` properties:

| Property | Type | Required | Description |
|---|---|---:|---|
| `userId` | string | Yes | Player submitting the answer. |
| `questionId` | string | Yes | Question being answered. |
| `answer` | string | Yes | Submitted answer text. |

### Responses

#### 200 OK

```json
{
  "correct": true,
  "playerAScore": 3,
  "playerBScore": 1
}
```

Response schema: `SubmitAnswerResponse`.

#### 400 Bad Request

Returned for invalid or incomplete JSON request data.

```json
{
  "title": "One or more validation errors occurred.",
  "status": 400,
  "errors": {
	"QuestionId": ["The QuestionId field is required."]
  }
}
```

#### 500 Internal Server Error

If the match does not exist, the service throws `Exception("Match not found")`. Persistence or completion-notification failures can also result in a server error.

# Notification domain

## POST `/events`

### Purpose
Creates an event log entry for a user.

### Request

Headers:

```http
Content-Type: application/json
```

Body schema:

```json
{
  "type": "MATCH_COMPLETED",
  "userId": "player-a",
  "payloadJson": "{\"matchId\":\"match-2026-0001\",\"winner\":\"player-a\"}"
}
```

`CreateEventRequest` properties:

| Property | Type | Required | Description |
|---|---|---:|---|
| `type` | string | Yes | Event type. |
| `userId` | string | Yes | User associated with the event. |
| `payloadJson` | string | Yes | JSON payload represented as a string. |

### Responses

#### 202 Accepted

The current controller returns `202 Accepted`, although the event is persisted synchronously before the response is sent.

```json
{
  "id": 42,
  "type": "MATCH_COMPLETED",
  "userId": "player-a",
  "payloadJson": "{\"matchId\":\"match-2026-0001\",\"winner\":\"player-a\"}",
  "createdAt": "2026-09-24T18:45:00Z"
}
```

Response schema: `EventResponse`.

#### 400 Bad Request

Returned for invalid or incomplete JSON request data.

```json
{
  "title": "One or more validation errors occurred.",
  "status": 400,
  "errors": {
	"Type": ["The Type field is required."]
  }
}
```

#### 500 Internal Server Error

Possible if event persistence fails.

> This endpoint returns `202 Accepted`, not `201 Created`.

# Service contracts

The HTTP controllers delegate to these domain service interfaces:

| Service | Operations |
|---|---|
| `IAuthService` | `RegisterAsync`, `LoginAsync`, `GetUserAsync` |
| `IQuestionService` | `GenerateAsync` |
| `ILobbyService` | `LockAsync` |
| `IGameplayService` | `CreateMatchAsync`, `GetMatchAsync`, `GetNextQuestionAsync`, `SubmitAnswerAsync` |
| `IStatisticsService` | `RecordResultAsync`, `GetStatsAsync`, `GetHistoryAsync`, `GetLeaderboardAsync` |
| `INotificationService` | `LogEventAsync`, `GetUserEventsAsync`, `UpdatePrefAsync` |

## Inter-domain service interaction notes

- `GameplayService` calls `INotificationService` for `MATCH_CREATED` and `MATCH_COMPLETED` events.
- `GameplayService` currently uses an internal static mock-question collection for gameplay questions.
- `QuestionService` independently reads questions and categories through `IQuestionRepository`.
- `StatisticsService` does not currently get invoked automatically by `GameplayService` when a match finishes; result recording is exposed as a separate HTTP operation.
- Notification preferences use string user identifiers, while identity and statistics contracts use GUID user identifiers. This reflects the current domain contracts and should be normalized if these domains are later joined by foreign keys.
